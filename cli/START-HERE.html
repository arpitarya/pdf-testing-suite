No install required

pdfsuite

Compares candidate PDFs against golden references and writes a report that shows every difference on the page.

No global command, no project to set up — the only requirement is Node 20 or newer. Check with node --version.

Run it

Four paths, in this order: the golden PDFs, the candidates, a pairs.json saying which file matches which, and a directory for the reports.

$ node /path/to/this/folder/dist/index.js compare ./golden ./candidates ./pairs.json ./reports

The paths you pass are relative to your working directory, not to this folder. Only the path to dist/index.js points in here.

Build the command

pairs.json

Every pair is explicit, so nothing is ever compared by accident. Paths are relative to the golden and candidate directories — never absolute, so the file works on any machine.

idgolden filecandidate file

Save that as pairs.json. An entry naming a file that does not exist stops the run — a missing candidate usually means generation dropped a document, which is the regression most worth catching.

Skipping a page

For a page that always differs — a print date, a barcode — add "skipPages": [6] to that pair. It is 1-based, and it exempts the whole page, visibly, in the report. It is the only way to exempt anything.

What you get

FileWhat it is for
report.htmlThe one to open. Both pages side by side with every change boxed and labelled, the pixel-difference heatmap, and a per-page list of what changed. Print to PDF to share it.
report.jsonPer-page metrics and verdicts, for a script to read.
report.csvOne row per pair × page, for a spreadsheet.
junit.xmlOne testcase per page. Jenkins, GitLab and GitHub Actions render it natively, giving per-page history for free.

Pick fewer with --format junit,json — the HTML report is the slow one, because it renders and embeds every page image.

What counts as a difference

A page fails if anything changed — wording, pixels, or position.

There is no tolerance to tune. The question a report answers is "did anything change?", and a knob that lets a real change be declared acceptable only hides it. A page present on one side only fails too.

An older pairs.json carrying defaults or thresholds still loads; those keys are ignored and the run says so.

Exit codes

CodeMeaning
0every pair passed — nothing differed
1at least one pair differs
2the tool could not run — bad arguments, unreadable PDF, an unresolved pair, zero pairs

1 versus 2 is what lets a pipeline tell "the PDFs regressed" from "the job is broken". Zero resolved pairs is an error, never a pass.

Use --fail-on none to always exit 0 and just collect reports.

If it does not run

Cannot find package '@napi-rs/canvas'
The node_modules folder next to dist was not copied. Copy the whole folder, not just dist.
Failed to load native binding, or a missing .node file
This folder was built for a different operating system or CPU. It carries one compiled renderer and cannot adapt. Two ways out: run npm install in this folder, if it can reach an npm registry — that replaces the renderer with the right one for your platform. Otherwise ask for a folder built for you: sh scripts/make-portable.sh --target darwin-arm64 (darwin-x64, linux-x64-gnu, win32-x64-msvc), or a lean one with --lean, which works on any platform.
macOS refuses to load it
A binary that arrived by download or shared drive rather than through npm gets quarantined. Clear the flag on the folder: xattr -dr com.apple.quarantine .
Unexpected token, or a syntax error on startup
Node is too old. node --version must be 20 or newer.

node dist/index.js --help lists every command, and node dist/index.js compare --help every flag.

A note on reading the numbers

Both sides of a comparison are rendered on the same machine, so a run is always self-consistent. Across operating systems it is not: a PDF that does not embed all its fonts falls back to the host's, so a pixel percentage from a Mac and one from Windows are not strictly comparable. Keep a baseline on one platform.
